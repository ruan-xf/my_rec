关键形状变化总结  
```
阶段	形状变化	说明
输入	[2, 128] × 3	三个特征的索引序列
Embedding	[2, 128, 20] × 3	每个特征嵌入到 20 维
拼接	[2, 128, 60]	三个特征拼接（60=20×3）
Transformer	[2, 128, 512]	序列编码，维度扩展到 512
取首token作为聚合表示	[2, 512]	取首token + Linear+Tanh
输出	[2]	回归预测值
```

这里实际发生了两步：  

encoder_outputs[0]（即 last_hidden_state）= 全部 128 个位置的最后一层输出，形状 [2, 128, 512]  
sequence_output[:, 0] — 只取序列的第一个 token（[CLS]），形状从 [2, 128, 512] → [2, 512]（这才是"序列→单向量"的步骤）  
self.pooler (Linear(512,512) + Tanh) — 维度不变，[2, 512] → [2, 512]  
图中把这两步合并成"池化"确实不够准确，而且"池化"这个名字容易让人误解为某种 pooling operation（如 mean pooling），但实际上只是取了 CLS token 再加了一个形状不变的线性变换。  

这个命名的历史来源是 BERT 原论文：取 [CLS] token 的向量作为整个序列的"聚合表示"用于分类任务，当时就把这一步叫做"pooling"——但它本质上就是个索引 + 线性变换，不是 max pooling / average pooling 那种操作。
