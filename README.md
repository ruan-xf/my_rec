使用类目特征将采样样本划分为四大类  
- 1 类目正确 + 物品正确
- 0.8 类目正确 + 同类错误物品
- 0.4 类目正确 + 不同类错误物品
- 0 类目错误 + 物品正确/错误


要注意任务类型的转换（二分类→回归）  
原论文  
- 二分类点击预测
- 输出为 {0,1} 二元标签
- 交叉熵损失
- 典型的二分类指标 AUC

调整为  
- [0,1] 连续值的预测
- MSE（均方误差）与MAE（平均绝对误差）为核心评估指标，mse为训练时的损失函数
- 验证 / 测试集仅保留用户真实交互样本（统一标签 1.0），MAE=mean (| 模型预测分数−1.0|) 可直接量化模型对真实偏好的打分准确性：MAE 越小，说明模型对用户真正想要的物品评分越接近满分，排序能力越强，也贴合工业级排序的实际应用逻辑



## 关于模型参数
反复确认对齐bst的参数设置  
一是要明确这些数量关系  
  1. hidden_size 必须得是 num_attention_heads 的整数倍
  2. ALBERT 的 FFN 中间层维度通常是 hidden_size * 4
二是要注意对齐原论文 1 层 8 头 的设置，预训练权重会更深层，而默认参数设置的 64 头比预训练权重的设置还要大得多  


论文中的 transformer block: 1 原来就是 1 层的意思，之前不知道就使用了num_hidden_layers的默认设置...恐怖的参数量造成龟速的训练和大量的内存/显存占用，而现在，完全地用bst论文的设置得到了对比更优并可以用来分析长距离依赖的结果也达到了复现的目的  


以下通过参数对比来说明参数作用  
使用的参数  
- `num_hidden_layers = 1`
- `num_hidden_groups = 1`（层组数）
- `inner_group_num = 1`（每组内层数）
- "num_attention_heads": 8 

与自然语言预训练权重中的设置：  
- "num_attention_heads": 12
- "num_hidden_groups": 1
- "num_hidden_layers": 12
- `inner_group_num = 1`


1. 编码器层数 num_hidden_layers（最核心差异）
含义：Transformer 编码器的堆叠数量，决定模型特征提取深度与长距离依赖的建模能力  
差异：本研究仅使用 1 层；NLP 预训练使用 12 层（深度架构）。  
本质区别：  
自然语言文本存在复杂的语义嵌套、长距离指代、语法逻辑，必须依靠深层编码器逐层提取抽象语义特征；  
电商用户行为序列为结构化的交互数据（用户 ID、物品 ID、类目 ID），特征模式简单，仅需单层编码器即可完成用户兴趣的特征融合与长距离依赖建模。  


2. 注意力头数 num_attention_heads
含义：多头注意力的并行头数量，用于从多个独立子空间捕捉不同维度的特征关联。  
差异：本研究使用 8 头；NLP 预训练使用 12 头。  
本质区别：  
NLP 需要 12 个注意力头捕捉语法、语义、上下文指代等复杂特征；  
购物推荐仅需捕捉时序依赖、类目偏好、物品相似度、短期 / 长期兴趣等有限维度  


结论：电商用户行为序列是低维度、结构化的离散特征，远低于自然语言的语义复杂度，1 层 8 头轻量化 Transformer足以建模用户历史交互与候选物品的匹配关系，无需深层多头的冗余结构  

## 为什么是albert
transformer -> bert -> albert  

与transformer完整的 encoder-decoder 不同，bert只使用了encoder，只使用encoder这点与bst的论文相同  
而albert相较于bert又减少了嵌入层参数  
与bert词嵌入矩阵和隐藏层维度一样大的做法不同，ALBERT 的嵌入层因子分解会先得到词的低维嵌入，再映射到隐藏层的维度，即便词表长度 V 很大，通过降低嵌入维度 E，仍然能显著减少参数。  
下面根据这里的描述对我的任务中这部分节省的参数量进行计算  

推荐系统中有多个特征，用最稀疏的物品进行估算  
O(V×H) -> O(V×E+E×H)  
v: 3652290 （训练集物品数）  
E: 60 （设置的嵌入维度，包含所有特征）  
H: 512  

V\*(H/3) -> V\*(E/3) + E\*H  
```
>>> v,e,h = 3652290, 60, 512
>>> a1 = v*(h//3)
>>> a2 = v*(e//3)+(e//3)*h
>>> a1, a2
(620889300, 73056040)
>>> a2/a1
0.11769653624245095
```
按float32（4 字节）算，节省的这部分参数量相当于2.19G的显存  
这使我能够在8G显存的机器上运行训练  

另外，bert类模型是双向注意力，我未确定双向的注意力在我的任务中是否必要  

## 具备长距离依赖的捕捉能力了吗？
长距离依赖存在的两个方面：注意力热力图和指标随区间长度变化的趋势  

一是热力图，分析注意力模式时不可以平均注意力权重，每个头本来有不同的注意力模式的，在关注的位置和强度上各有不同，这点的发现可以说明其在利用长距离的信息  

二是考虑不同长度样本上的表现，通过以下的过程得到了有价值的发现：  
首先只是常规的分组，然后可视化一系列随序列长度变化而变化的指标，注意到cumulative_mae并确定了其意义，进一步查看逐区间的mae收尾分析  

### 先按`cat_is_pad`分组查看是否存在分组差异

关键发现  
1. ALBERT：类目推理场景MAE大幅下降35.0%，推理能力极强
2. CNN：MAE下降21.3%，有一定推理能力
3. MLP：几乎无变化，无推理能力

### 再考虑不同序列长度的表现差异，可视化能快速揭示这一点
是的，一次性绘制多个随序列长度而变化的多个指标，并且使用tensorboard可以进行筛选和交互，有了意外的、有价值的发现  

采样分布均衡：全局/分组 三组数据分布曲线重合，无数据偏差，性能差异源于模型能力  

cumulative_mae(l) = E[error | L ≤ l] 的趋势变化反映了新增样本的性能  
若查看该趋势，可发现不同模型会截然不同：  
- ALBERT：**单调下降**（序列越长，性能越好）
- CNN：**先降后升的U型**（中等长度最优，超长退化）

CNN的U型拐点在分组中不同：  
- 类目推理组（True）：拐点≈30
- 真实类目组（False）：拐点≈200-300

### 进一步以区间mae解读趋势信息
cumulative_mae的下降或上升能够揭示新增的样本是表现得更好还是更差，但具体的便需要查看逐区间的mae了  

针对 CNN 在`cat_is_pad`分组后出现了不同的趋势，将根据对应趋势做更细的区间拆分，定位最优性能的序列长度阈值。  

核心发现  
1. 类目推理组（True）：
   - 最优序列长度≈**30**，短序列即可捕获强关联信号
   - 超过30后性能开始恶化
2. 真实类目组（False）：
   - 最优序列长度≈**200-300**，需要长序列做细粒度物品区分
   - 超过300后性能显著退化
